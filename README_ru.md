# Gerber2MSLA

Засветка фоторезиста плат на MSLA-принтере (Anycubic Photon Mono X 6Ks): маска в точных
пикселях экрана становится файлом принтера, позже плата — из гербера.

ЖК-экран засвечивает ЦЕЛЫЕ пиксели, поэтому утилита работает в пикселях экрана — на этом
принтере 5760 x 3600, 34 мкм на пиксель по профилю UVtools/PrusaSlicer (это профиль, а не
проверенный паспорт). Файл принтера — однослойный `.px6s`; к принтеру ничего не отправляется,
лазера здесь нет.

Состояние: тестовые маски, привязанные к пикселям (`bars`, `grid`), работают как
`gerber2msla masks …`; конвертер (PNG → `.px6s`) — следующий шаг плана
`techdocs/handoff/deepseek/plan_2026_10_23_png2px6s.md`.

## Тестовые маски

```
gerber2msla masks bars   --screen-px WxH --pixel-um PXxPY -o out/bars.png \
                         [--widths-mm 0.2,0.15,0.1 | --widths-px 6,5,4,3,2,1] \
                         [--lines 5] [--at X,Y] [--mirror] [--invert] [--marker|--no-marker]
gerber2msla masks grid   --screen-px WxH --pixel-um PXxPY -o out/grid.png \
                         [--width-mm 50 --height-mm 40] [--line-mm 0.2 | --line-px 6] \
                         [--gap-mm 0.15 | --gap-px 4] [--direction both|x|y] …
gerber2msla masks square --screen-px WxH --pixel-um PXxPY -o out/square.png \
                         [--side-mm 100 | --side-px N] [--line-mm 0.2 | --line-px 6] …
gerber2msla masks plate  --screen-px WxH --pixel-um PXxPY -o out/plate.png \
                         [--plate-mm 70x78] [--margin-mm 2] [--grid-mm 30x30] \
                         [--widths-mm … | --widths-px …] [--lines 5] …
```

`--screen-px` и `--pixel-um` **обязательны и без умолчаний**: выдуманное число хуже отказа.
Для Anycubic Photon Mono X 6Ks профиль принтера в UVtools (и `Anycubic Photon Mono X 6Ks.ini`
от PrusaSlicer) говорит 195.84 x 122.4 мм на 5760 x 3600 px, то есть **34 мкм на пиксель** —
это ПРОФИЛЬ, а не проверенный паспорт и не замер. Настоящий пиксель меряется квадратом
(ниже), по каждой оси отдельно.

```sh
.venv/bin/gerber2msla masks bars --screen-px 5760x3600 --pixel-um 34x34 \
    -o out/bars.png --widths-px 6,5,4,3,2,1
.venv/bin/gerber2msla masks grid --screen-px 5760x3600 --pixel-um 34x34 \
    -o out/grid.png --width-mm 50 --height-mm 40 --line-px 6 --gap-px 4
.venv/bin/gerber2msla masks square --screen-px 5760x3600 --pixel-um 34x34 \
    -o out/square.png --side-mm 100 --line-mm 0.2
.venv/bin/gerber2msla masks plate --screen-px 5760x3600 --pixel-um 34x34 \
    -o out/plate.png --plate-mm 70x78
```

* Пиксель может быть неквадратным — две величины, по оси.
* `bars` — группы линий с промежутком, равным ширине: горизонтальный блок (разрешение по Y)
  и вертикальный (по X), каждый квадратный, чтобы оси были сравнимы;
* `grid` — прямоугольник, заполненный линиями: первая линия вплотную к ближнему краю,
  линия только целиком, остаток у дальнего края — промежуток;
* `square` — замкнутый контур; сторона (по умолчанию 100 мм — лазерные 150 мм на этот
  экран не влезают) и линия — целые пиксели СВОЕЙ оси. Отчёт печатает
  `pixel_um_x = measured_x_mm / n_x * 1000` (и Y) с числами этого заказа: измерь обе
  стороны штангенциркулем, ОТ наружного края до наружного, и подставь результат в
  `--pixel-um`. Диагонали — только проверка замера (`d1 = d2` ожидается): у жёсткой сетки
  экрана перекоса нет, есть масштаб;
* `plate` — все тесты на ОДНОЙ засветке: рамка квадрата (пластина минус поле), одна буква
  F, `bars` в левой половине и `grid` в правой. Раскладка фиксированная: подписей на маске
  нет. На пластине умолчание `grid` — 30 x 30 мм: одиночные 50 x 40 в половину не влезают,
  и отчёт говорит это числами. Пересечение или выход за рамку — отказ, молча не урезается;
* каждая ширина становится `n = round(ширина / шаг)` пикселей СВОЕЙ оси, и отчёт печатает
  запрошенную ширину рядом с ФАКТИЧЕСКОЙ: 0.100 мм на пикселе 34 мкм — это 3 px =
  0.102 мм. Именно фактическое число и будет на пластине.
* `--widths-px 6,5,4,3,2,1` — та полоска, с которой стоит начинать на этом экране: шесть
  РАЗНЫХ ступеней по 34 мкм. Список в миллиметрах 0.2/0.15/0.1/0.08/0.06/0.05 дал бы
  6, 4, 3, 2, 2, 1 — две одинаковые группы, о чём утилита и предупреждает.
* ширину можно заказать в миллиметрах или в ЦЕЛЫХ ПИКСЕЛЯХ; эти две формы исключают друг
  друга. Промах мм-заказа больше 10 % объявляется: «0.050 mm along Y is drawn as
  34.0 um (-32 %)».
* каждый рисунок несёт букву **F** в верхнем левом углу, узор начинается правее неё;
  F несимметрична по обеим осям, поэтому зеркальная засветка (ножка справа) или
  перевёрнутая (перекладины внизу) видна на пластине. `--no-marker` выключает метку.
* белое — засвеченный пиксель: по умолчанию белые ЛИНИИ (негативный резист), `--invert`
  меняет это местами, `--mirror` отражает готовую картинку по X.
* отчёт — экран, пиксель, ширины запрошенные и фактические, зеркало, полярность —
  пишется ещё и в текстовый кусок PNG `msla_tests`, чтобы файл помнил, что он такое.

## Запись файла принтера

```sh
.venv/bin/gerber2msla write out/plate.png --template real.px6s \
    -o out/plate_25s.px6s --exposure-s 25 [--mirror-x]
```

* **шаблон** — настоящий однослойный `px6s` этого принтера (версия 517), сделанный
  слайсером: всё машинное (подъёмы, скорости, блоки `MACHINE`, `EXTRA`, `SOFTWARE`,
  `MODEL`) копируется байт в байт. Пишутся только слой, оба времени, число слоёв и превью;
* маска — ровно разрешение шаблона, режим `L`, значения 0/255; иное — отказ с найденными
  числами;
* **ловушка нижних слоёв:** в однослойном файле слой 0 — НИЖНИЙ, и принтер светит его
  временем нижних слоёв. Оба времени ставятся в `--exposure-s`, нижних слоёв — 1; отчёт
  говорит, что именно записано;
* `--mirror-x` отражает маску до кодирования и по умолчанию ВЫКЛЮЧЕН: в файле флага
  зеркала нет, решение за тобой, проверка — меткой F на пластине. Отчёт говорит, включён ли;
* `LightPWM` в `px6s` v517 не хранится вовсе; отчёт пишет это словами, а не выдумывает
  яркость;
* отчёт печатает и число белых пикселей с площадью в мм², и путь результата.

Как довезти до принтера: сначала открыть файл в **UVtools** — слой должен совпасть с
маской, а времена быть твоими, — и только потом нести на принтер. Сама утилита с принтером
не разговаривает.

## Чтение файла принтера

```sh
.venv/bin/gerber2msla dump out/plate_25s.px6s [-o out/layer.png]
```

* печатает то, что говорит САМ ФАЙЛ, без толкований: версию и число блоков, имя станка и
  формат слоя, разрешение и пиксель, оба времени, число нижних слоёв и число слоёв, высоту
  и скорости подъёма, адреса всех блоков; у каждого слоя своя строка — адрес, длина, подъём,
  время, число ненулевых пикселей;
* `-o` сохраняет слой 0 серым PNG (`L`) — ту же картинку, что кодировал `write`, поэтому
  `masks plate` → `write` → `dump -o` → PNG — проверка без принтера;
* файл, который не `px6s`, — отказ одной строкой и код 2, PNG не появляется;
* `dump` не добавляет знания о байтах: блоки уже разобрал `gerber2msla/px6s.py`, а формат
  записан в [docs/format_px6s.md](docs/format_px6s.md). Время слоя и нижнее время из шапки
  печатаются оба — ловушку однослойного файла видно прямо в файле.
